# Slop-детектор — чек-лист AI-клише

«AI-слоуп» — это не ощущение, а конечный список повторяющихся паттернов, которые модели выдают по умолчанию. Прогони экран по чек-листу; каждый хит — это находка, которую нужно либо исправить, либо осознанно защитить.

## Как проводить аудит

1. Посмотри на экран целиком (скриншот через `design-loop`, либо читай код).
2. Пройдись по шести категориям ниже; отмечай хиты.
3. Ответ в формате таблицы: **паттерн → где найдено → чем заменить**.
4. Итог: счёт «N хитов из 60» и топ-3 исправления по влиянию.
5. При правках: один хит — одна точечная замена, не переписывай экран целиком.

Важно: одиночный хит — не приговор (используемый по делу градиент — норм). Сигнал — скопление: 10+ хитов означают, что дизайн собран по умолчанию, а не по решению.

## Цвет (10)

| # | Паттерн | Замена |
|---|---|---|
| 1 | «AI-бежевый» фон `#F5F0E8`-класса без связи с брендом | Осмысленная нейтраль: тёплая или холодная под характер продукта, либо чистый белый/чёрный |
| 2 | Фиолетово-синий градиент (`#667eea → #764ba2` и родня) как главный приём | Один сильный акцентный цвет; градиент — только если есть причина |
| 3 | Primary = стандартный Tailwind `blue-500/#3B82F6` | Акцент, выбранный под бренд и проверенный на контраст |
| 4 | Чистый `#000000` текст на белом | `#111`–`#1A1A1A` для тела, чёрный — только display |
| 5 | Ровно один серый на все случаи (`text-gray-500` везде) | Шкала из 5–7 нейтральных ступеней с ролями |
| 6 | Неоновые акценты (cyan/lime) в светлом интерфейсе | Приглушённый акцент той же температуры |
| 7 | Радужный градиент на кнопке/заголовке | Плоский цвет + вес/размер для выделения |
| 8 | «Тёмная тема = серый фон + нетронутый белый текст» без пересчёта палитры | Полная пересборка нейтральной шкалы для тёмного фона, акцент осветлить |
| 9 | Одинаковый hover (подсветка) у всех интерактивных элементов | Свои состояния по типу элемента: кнопка/ссылка/карточка |
| 10 | Полупрозрачный белый оверлей поверх фото на каждом hero | Затемнение с направлением (градиент к краю), scrim по контрасту текста |

## Режим diff

Если аудит идёт по diff (PR / ветка), проверяй только добавленное/изменённое, но читай окрестности: хит засчитывается, если новый код повторяет паттерн на экране.

## После аудита

- Хиты из «Копирайта» и «Изображений» — чинятся сразу, они не требуют дизайна.
- Хиты из «Цвета» и «Типографики» — сначала проверь `DESIGN.md`: если токены уже зафиксированы, дыра в применении; если нет — предложение прогнать `tokens`.
- Результат аудита по значимым решениям дописывай в appearance-ledger (см. `design-memory`).
