# Визуальная петля — скриншот → вердикт → фикс

Код врёт: красиво написанный компонент может выглядеть сломанно. Любое заявление о качестве дизайна («стало лучше», «готово», «выглядит чисто») делается **только по свежему скриншоту после правок**, никогда — по чтению кода или памяти о прошлой итерации.

## Инструменты

- Есть `chrome-devtools-mcp` (или любой браузерный инструмент агента: browser-use, playwright и т.п.) → используй его: навигация, resize вьюпорта, скриншот.
- Инструментов нет → запусти статический файл/дев-сервер и попроси пользователя приложить скриншот; не делай вид, что проверил.

## Петля

1. **Подготовка.** Открой страницу. Вьюпорты: десктоп `1440×900` и мобильный `390×844`. Если правился конкретный компонент — скринь его в изоляции и на месте.
2. **Вердикт по скрину.** Прогони по картинке:
   - быстрый `audit` — чек-лист `design-slop-detector`;
   - `critique` — 6 измерений 0–10, когда нужна полная оценка.
3. **Фиксы.** Не больше трёх изменений за итерацию — иначе не поймёшь, что помогло. Правки — в токенах и структуре, не точечные хаки.
4. **Повторный скрин.** Тот же вьюпорт, то же состояние. Сравни с предыдущим: каждое заявленное улучшение должно быть видно.
5. **Выход.** Вердикт «готово» = свежий скрин без новых хитов + все правки подтверждены. Иначе — следующая итерация (максимум 3, дальше — эскалация пользователю с вариантами).

## Чеклист по скрину (быстрая версия)

- Иерархия читается за 2 секунды: что на экране главное?
- Вертикальный ритм: отступы одного вида равны, разных — различимы.
- Типографика: не более 3 размеров в кадре, выравнивания осмысленны.
- Контраст: текст различим, `muted` не читается как «сломанный».
- Перегруз: есть ли элемент, который можно убрать без потери смысла.
- Мобильный скрин: ничего не обрезано, тап-цели ≥44px.

## Формат ответа

```
Итерация N — вердикт
Скрин: desktop ✓ / mobile ✓
Хиты: <список или «нет»>
Оценки (если critique): иерархия 7 · типографика 6 · цвет 8 · ритм 5 · моушн — · характер 7
Фиксы этой итерации: 1) … 2) … 3) …
Статус: продолжаю | готово (по скрину после правок)
```

## Правила

1. Один скрин — один вьюпорт. Нельзя судить мобильную версию по десктопной картинке.
2. Скриншот «до» сохраняй до правок, чтобы сравнение было честным.
3. Если правка не видна на повторном скрине — она не работает; разберись, прежде чем добавлять новую.
4. Результаты значимых итераций (принятые фиксы, отвергнутые направления) — в appearance-ledger (`design-memory`).
