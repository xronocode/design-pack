# Библиотека стилей

12 стилей, каждый — готовая система: палитра, шрифтовая пара, шкалы отступов и радиусов, тени, моушн, сценарии применения и границы. Стили — это ammunition, не догма: комбинируй, адаптируй, но любое отклонение фиксируй в `DESIGN.md`.

## Флоу выбора направления (6 → 3 → 1)

1. Прочитай бриф: продукт, аудитория, носитель, настроение, ограничения бренда.
2. Сгенерируй **6 кандидатов**: 3–4 из каталога (бери неочевидные тоже) + 2 гибрида/собственных. Кандидаты должны различаться характером, а не деталями.
3. Отброси 3 слабых (не подходят сценарию, конфликтуют с брендом, скучные). Оставь 3.
4. Покажи тройку: для каждого — название, 2–3 строки сути, ключевые токены (шрифтовая пара, палитра 3 цветами), один аргумент «за» и один риск. Если есть возможность — мини-мокап каждого направления.
5. Пользователь выбирает → прогони `tokens` (см. `design-vocabulary`) и зафиксируй в `DESIGN.md`.

Никогда не выбирай финальный стиль за пользователя молча — направление всегда согласуется.

## Правила применения стиля

- Токены переносятся в проект как CSS-переменные / Tailwind-тема целиком, без «по мотивам».
- Один проект — один стиль. Гибрид допустим, но описывается явно: «база editorial + сетка swiss».
- Внутри стиля соблюдай его «нельзя»: например, тени запрещены в `swiss`, скругления — в `blueprint`.
- При `restyle` существующего продукта сравни токены до/после и обнови `DESIGN.md`.

## Расширение библиотеки

Новый стиль добавляй по той же схеме, что и каталожные: характер в одном предложении → палитра с ролями → шрифтовая пара со scale → шкалы → моушн → сценарии → нельзя → образец. Стиль без образца не считается завершённым.
